# รายงานตรวจสอบจุดบกพร่อง SLTS (ก่อนปรับเป็น v2.0.0)

ตรวจเมื่อ 13 พ.ย. 2569 จากโค้ด `erkawit/slts` commit `44d0d83`
สถานะ: ✅ แก้แล้วใน v2.0.0 • 🟠 ต้องทำเพิ่มนอกโค้ด (ตั้งค่า/ปฏิบัติ) • 🔵 แนะนำทำในรอบถัดไป

บันทึกจุดบกพร่องที่เกิดขึ้น **หลังจากนี้** ดูได้ในแอป: เมนู → ศูนย์ผู้ดูแลระบบ → จุดบกพร่อง (เก็บอัตโนมัติจากทุกเครื่อง)

## A. ความปลอดภัย (ร้ายแรงที่สุด — ควรแก้ก่อนใช้งานต่อ)

| # | ปัญหา | ผลกระทบ | สถานะ / วิธีแก้ |
|---|---|---|---|
| A1 | `GET ?action=get_users` ของ Apps Script ส่ง **รหัสผ่านทุกคนแบบอ่านออก** และ URL นี้ฝังอยู่ใน `app.js` สาธารณะ | ใครก็ได้ดึงชื่อผู้ใช้+รหัสผ่านทั้งหมด | ✅ ย้ายการล็อกอินไปเซิร์ฟเวอร์ (`/api/slts`), เก็บ scrypt hash, API ไม่ส่งรหัสผ่านออกเลย, Apps Script ล็อกด้วย `BRIDGE_SECRET` |
| A2 | รหัสผ่าน admin ฝังในซอร์สโค้ด (`app.js`, `Code.gs`) บน GitHub สาธารณะ | เข้าระบบเป็น admin ได้ทันที | ✅ ลบออกจากโค้ด + บังคับเปลี่ยนรหัสตอนเข้าใช้ครั้งแรก • 🟠 ทำ repo เป็น Private (รหัสเก่ายังอยู่ในประวัติ git) |
| A3 | ล็อกอินตรวจในเบราว์เซอร์เท่านั้น (เทียบกับ localStorage) | แก้ localStorage ก็เป็น admin ได้ | ✅ ตรวจที่เซิร์ฟเวอร์ + token ลงลายเซ็น HMAC, เปลี่ยนรหัสแล้วตัดเซสชันเก่าทุกเครื่อง, จำกัดล็อกอินผิด 10 ครั้ง/15 นาที |
| A4 | Apps Script ไม่ตรวจสิทธิ์: ใครก็ POST `delete`, `save_user`, `edit_record` ได้ และสิทธิ์แก้ไขเชื่อค่า `role`/`uploader` ที่เครื่องส่งมา | ลบ/แก้ข้อมูลคดี สร้างผู้ใช้ปลอมได้ | ✅ ทุกคำสั่งต้องมี token, ลบได้เฉพาะ admin, แก้ได้เฉพาะเจ้าของหรือ admin, Local Advisor จัดการได้เฉพาะผู้ใช้ในศาลตัวเอง (ตรวจที่เซิร์ฟเวอร์) |
| A5 | Google Sheet เปิดสาธารณะ (หน้าเว็บอ่าน CSV ผ่าน `gviz`) | ที่อยู่/เลขคดีรั่วไหล | ✅ ตัดการอ่าน CSV ออกจากหน้าเว็บ • 🟠 ตั้ง Sheet เป็น Restricted |
| A6 | ข้อมูลส่งหมายถูกส่ง/แคชโดยไม่ต้องล็อกอิน | ข้อมูลส่วนบุคคลรั่ว | ✅ `get_data` ต้องล็อกอิน, Service Worker ไม่แคช `/api/*` |

## B. ภาพถ่าย/ข้อมูลสูญหาย

| # | ปัญหา | สถานะ |
|---|---|---|
| B1 | `captureAndProcessPhoto` — `catch` อ้าง `uploadPayload` ที่ประกาศใน `try` → ReferenceError ภาพหายเมื่อเกิดข้อผิดพลาด | ✅ ประกาศนอก `try` + ไม่ล้างฟอร์มเมื่อผิดพลาด |
| B2 | กันซ้ำด้วย "ชื่อไฟล์" → ถ่ายคดีเดิมซ้ำ (ถ่ายใหม่/ถ่ายหลายมุม) ภาพที่ 2 ถูกทิ้งเงียบ แต่ขึ้นว่า "ถ่ายภาพสำเร็จ" | ✅ ทุกภาพมีรหัส `cap_…` ไม่ซ้ำ กันซ้ำด้วยรหัสเท่านั้น |
| B3 | Watchdog คิว 45 วิ < timeout อัปโหลด 60 วิ → เน็ตช้าแล้วส่งซ้ำ ได้แถว/ไฟล์ซ้ำ | ✅ watchdog 90 วิ + เซิร์ฟเวอร์กันซ้ำด้วย `clientUploadId` (idempotent) |
| B4 | บันทึกคิวลง IndexedDB แบบไม่รอ (clear แล้ว put) ปิดแอปทันทีหลังถ่าย ภาพอาจหาย | ✅ "คลังภาพในเครื่อง" เขียนเสร็จจริงก่อนเข้าคิว + กู้คืนภาพที่หลุดจากคิวอัตโนมัติ |
| B5 | เชื่อ `navigator.onLine` อย่างเดียว (ต่อ Wi-Fi ไม่มีเน็ต = online) → ส่งล้ม 5 ครั้งแล้วติดสถานะ failed | ✅ ตรวจ `/api/health` จริง, ข้อผิดพลาดชั่วคราวไม่นับครั้ง, พักแล้วลองใหม่ทุก 30 วิ, ส่งทันทีเมื่อสัญญาณกลับ |
| B6 | แชร์เส้นทางให้ผู้ใช้อื่น: ส่งแบบไม่รอผล แต่แจ้ง "แชร์สำเร็จ" เสมอ (แม้ออฟไลน์) | ✅ รอผลจากเซิร์ฟเวอร์และแจ้งข้อผิดพลาดจริง + เพิ่มแชร์ด้วย QR |
| B7 | อัปโหลดล้มเพราะเซสชันหมดอายุ → นับเป็นภาพเสีย | ✅ พักคิว ขอให้ล็อกอินใหม่ แล้วส่งต่อ |

## C. ออฟไลน์ / PWA / ประสิทธิภาพ

| # | ปัญหา | สถานะ |
|---|---|---|
| C1 | Service Worker ไม่แคชไลบรารีจาก CDN (Tailwind, SweetAlert2, Leaflet…) → เปิดแอปตอนไม่มีเน็ตหน้าจอพัง | ✅ แคชแบบ stale-while-revalidate |
| C2 | ชื่อแคช SW ต้องแก้มือ (`v94`) และ `?v=` ของสคริปต์ไม่ตรงกัน → มือถือได้ไฟล์เก่า | ✅ ผูกกับเลขเวอร์ชันอัตโนมัติตอน build + แจ้ง "มีอัปเดตระบบ" |
| C3 | `img/logo.png` 2.2 MB โหลดทุกหน้า, manifest ระบุขนาดไอคอนผิด | ✅ ลดเหลือ 88 KB + ไอคอน 192/512 ถูกขนาด |
| C4 | ใช้ Tailwind Play CDN ในระบบจริง (คอมไพล์ CSS บนมือถือทุกครั้ง ~400 KB) | 🔵 build CSS ล่วงหน้าด้วย `tailwindcss` CLI แล้วเปลี่ยนเป็นไฟล์ `css/tailwind.css` (ต้องตรวจคลาสที่สร้างแบบต่อสตริงใน JS ก่อน) |
| C5 | `js/app.js` ไฟล์เดียว 26,000+ บรรทัด (1.4 MB) | 🔵 แยกเป็นโมดูล (auth, camera, queue, map, users) + minify; เริ่มจากส่วนที่แก้บ่อย |
| C6 | โฟลเดอร์ `public/` ถูก commit ทั้งที่อยู่ใน `.gitignore` (ไฟล์ซ้ำ 2 ชุด) | 🔵 `git rm -r --cached public` |
| C7 | `get_data` ดึงทุกแถวทุกครั้ง (แคช 1 นาที) ช้าลงตามจำนวนข้อมูล | 🔵 เพิ่ม `?since=` ดึงเฉพาะที่เปลี่ยน (ตาราง `summons` มี `updated_at` แล้ว) |
| C8 | `deploy.bat` ทำ `git add .` + commit + push อัตโนมัติ | 🔵 แยกขั้น commit ให้ตรวจก่อน |
| C9 | `build:apk` ใช้ `gradlew.bat` (Windows เท่านั้น) | ✅ เพิ่ม `build:apk` (macOS/Linux) และ `build:apk:win` |

## D. ขั้นตอนที่ต้องทำต่อ (เรียงตามลำดับ)

1. ทำตาม `docs/SETUP-NEON.md` ขั้นที่ 1–7 (ติดตั้ง Neon, deploy Apps Script ใหม่ + `BRIDGE_SECRET`, ย้ายข้อมูล, ขึ้น Vercel)
2. 🟠 ตั้ง Google Sheet เป็น Restricted และ GitHub repo เป็น Private
3. ให้ทุกคนเข้าระบบใหม่ 1 ครั้ง (เวอร์ชัน 2 ยกเลิกเซสชันแบบเดิม) — ผู้ใช้รหัสอ่อนจะถูกบังคับเปลี่ยน
4. ทดสอบภาคสนาม: เปิดโหมดเครื่องบิน → ถ่าย 2–3 ภาพ → ปิดแอป → เปิดใหม่ → ปิดโหมดเครื่องบิน → ภาพต้องขึ้นระบบเอง
5. ทดสอบแชร์ QR: PC จัดเส้นทาง → แชร์ → QR Code → มือถือกด "สแกน QR" (ปุ่มสีส้มบนหน้ากล้อง)
6. เปิดศูนย์ผู้ดูแลระบบ → จุดบกพร่อง สัปดาห์ละครั้ง: ระบุสถานะ/บันทึกวิธีแก้/เวอร์ชันที่แก้
7. ทุกครั้งที่แก้โค้ด: `npm run version:bump -- patch "สิ่งที่แก้"` → `npm test` → deploy
8. 🔵 รอบถัดไป: C4 → C5 → C7
